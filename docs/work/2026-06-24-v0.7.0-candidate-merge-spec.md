# v0.7.0 Candidate Merge Spec

Date: 2026-06-24

## Goal

Move the current v0.7.0 foundation work out of local `main` into a reviewable release-candidate branch without tagging or publishing a release.

## Scope

Included in the candidate checkpoint:
- HA NOVA health and calendar skills.
- Relay 0.2.3 bounded WebSocket event collection.
- Install/status/doctor integrity reporting.
- Trace helpers and semantic review hardening.
- Write preview, confirmation, output, diff, and delete-flow hardening.
- Documentation and tests for the above.

Excluded from this checkpoint:
- Gemini CLI to Google Antigravity migration.
- Dependency cleanup.
- Any release tag, GitHub release, package publish, or final install claim.

## Merge Path

1. Create `release/v0.7.0-candidate` from the current local checkpoint.
2. Commit the current foundation work there.
3. Push a draft PR for review only.
4. Keep the PR unreleased until the Antigravity migration lands as a separate reviewed delta.

## Rationale

This keeps the large tested foundation work reviewable while preventing a half-modernized v0.7.0 release. Google has announced that Gemini CLI individual/free/Pro/Ultra access is transitioning to Antigravity CLI, so the final release must account for that client-story change before tagging.

## Verification Before PR

- `npm run verify`
- `npm run dev:sync`
- `ha-nova version`
- `ha-nova status --json`
