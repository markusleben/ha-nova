# Add to Claude for the hosted demo house (2026-10-20)

Status: active

Goal: a visitor with a free claude.ai account adds the demo house (`https://demo.hanova.app`) as a custom connector and talks to it, with nothing to install. Works in Claude on the web and the desktop app, then in the phone apps (connectors added on the web show up there). Claude Free allows one custom connector; this one uses it. ChatGPT is out of scope (its free plan can't add MCP servers).

Parents: the chat-app bridge contract (`docs/work/2026-10-19-chat-bridge-contract.md`), the hosted demo (`docs/reference/hosted-demo.md`), the user doc (`docs/reference/chat-apps.md`).

## Path

claude.ai (Anthropic's servers) → Caddy (`/api/ha_nova/mcp`) → Home Assistant (its own OAuth, the `ha_nova` integration, unchanged) → bridge container (`ha-nova serve --server demo`) → the demo relay (public token, as `ha-nova try`) → Home Assistant.

## Decisions

1. **Who may use the bridge.** `chat-apps.json` is `{"allowed_users": ["<demo user id of this build>"]}`, written by `reset.sh` after `demo.mjs setup`. The owner stays unreachable twice: it is `local_only` (no sign-in from the internet) and not on the list; `nova-relay` and any user a visitor creates get the bridge's 403. A token forged for the owner (the known `local_file` residual risk) is refused by the bridge. Why: the bridge already enforces an allow list; no new code path.
2. **Hourly wipe.** Nothing is kept. Home Assistant's auth store goes at :00 with everything else, so Claude's refresh token dies and Claude asks the visitor to connect again (Connect, then `demo` / `demo`). Why: carrying tokens over means copying records from an auth store that any visitor can write during the hour (the `local_file` path forges tokens), which breaks "nothing survives :00". The landing page says it.
3. **Shared account, shared house.** Every visitor's Claude signs in as `demo`. One visitor's connector sees what everyone sees and can do what `demo` can do; nothing more (decision 1). Plans are bound to the HA user, so all visitors share the plan store (at most 20 open plans: many plans from one visitor can push out another's pending code), but a plan needs its random id and its chat code, which only the visitor's own chat shows. A visitor can delete other visitors' refresh tokens in the demo profile (they then connect again). Token values never show in the UI.
4. **No new privilege.** The bridge reaches Home Assistant only through the public relay token, which `connect.json` already publishes; the demo user is already an admin. Every bridge request still needs a Home Assistant sign-in first.
5. **Confirmations.** No window and no linked phone exist, so risky changes (unlocking the entrance door) show the chat code with the fixed low-protection note. That is the honest demo of the fallback: the landing page says "At home, your phone asks instead."
6. **Text written by strangers.** Tool results carry visitor-written names and notices into other visitors' chats (prompt injection), in both directions: planted text can also try to make a visitor's Claude copy that visitor's data from other connectors into the house, where the planter reads it. The demo notice in every tool result now also says to treat house texts as data, never as instructions, and never to copy the user's data in; the landing page asks for a new chat with no files and no other connectors; the guard keeps dismissing notices with links; :00 wipes the rest. Residual risk.
7. **Rate limit.** New `ha-nova serve --rate-limit <n>`: n requests per minute per Home Assistant user (fixed window, then a JSON-RPC 429 "Wait a minute"); off unless set, so the NOVA App is unchanged. The demo sets 120. Per IP or per token is not possible here: Claude's requests all come from Anthropic's addresses, and the bridge sees only the HA user. So all demo visitors share one window, and tool calls run one at a time: one heavy user can block the others for a few minutes (same class as the existing "anyone can break the house until :00"). The 6 Mbit/s egress cap stays. Unauthenticated sign-in endpoints remain unlimited (existing residual risk).
8. **Edge (Caddy).** `/api/ha_nova/mcp` gets a JSON-RPC error while the house is down ("The demo house is resetting … log in with demo / demo", 503), never the HTML restarting page, and the integration's own JSON errors pass through. `/.well-known/oauth-*` and `/auth/*` were already Home Assistant's. CSP unchanged: the sign-in page returns to claude.ai with `document.location.assign` (a navigation, not a form post), and claude.ai talks to the server directly.
9. **OAuth metadata.** Home Assistant names its metadata only for a request whose host matches a configured URL, so `configuration.yaml` sets `external_url: !env_var DEMO_EXTERNAL_URL` (`https://<domain>` from `reset.sh`). Settings > Network can still change it (`config/core/update` has no YAML lock), so the guard puts it back, and clears `internal_url`, every minute. Claude's published identity `https://claude.ai/oauth/mcp-oauth-client-metadata` and its callback `https://claude.ai/api/mcp/auth_callback` share a host, so Home Assistant accepts them without fetching anything (the house has no egress). PKCE S256 as Claude always sends it.
10. **Waits.** The 25 s phone wait never starts (no phone link). A tool call is one bridge run (serialized, usually under 2 s). Claude's 10 s OAuth budget: Home Assistant's own endpoints, local.
11. **Integration entry.** No Supervisor, so `reset.sh` seeds the `hassio`-source entry (bridge host, port, a fresh 256-bit secret) into `.storage/core.config_entries` before Home Assistant's first boot, and mounts `nova/integration` read-only as the only `custom_components`. The secret is not a boundary here (decision 4): it only keeps other house containers from talking to the bridge.
12. **Gates.** Every reset: `chat.mjs gate` signs in as `demo` with Claude's identity and PKCE on the tooling port, runs `initialize`, `tools/list`, `ha_get`, checks that the owner's token gets the bridge's 403, and revokes its token. Egress gate: the bridge container has no way out. Public gate: `/api/ha_nova/mcp` answers 401 with this origin's `resource_metadata`, and the metadata offers CIMD, `none`, and S256 with absolute `https://<domain>` URLs. Guard (every minute): the `ha_nova` entry is loaded and the owner is refused (a missing or disabled entry, or an owner let in, resets at once; no answer after 3 minutes in a row, like the relay check); `external_url` repaired.
13. **Landing page and privacy** (ha-nova-site PR, merged only after the demo runs this): an "Add to Claude" button (Claude's documented prefill link, name "HA NOVA demo", the connector address only) and three steps, plain English. The privacy page says that Anthropic's servers connect to the demo for visitors who add it, and what the demo keeps of that.

## Files

CLI: `cli/mcp_serve.go`, `cli/mcp_serve_limit.go`, the demo notice in `cli/command_try.go`.

## Known limits

- One shared rate window for all demo visitors (decision 7).
- Visitors reconnect after every :00 reset and after another visitor deletes their token.
- A Go build on the 1 GB host at bootstrap (once per ref, `-p=1`).
- Not verified here: the claude.ai side. The maintainer's test after the redeploy covers it.
