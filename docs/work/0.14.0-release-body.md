## New Features (draft)

- **Guided uninstall.** `ha-nova uninstall` now walks you through the Home Assistant side too: removing the NOVA Relay app, removing the repository, and revoking the "NOVA" access token. The cleanup checklist is always shown — even when Home Assistant is unreachable.
- **Update notices in every AI client.** Codex, OpenCode, Antigravity, and Hermes now surface HA NOVA updates during normal skill use; previously only Claude did.
- **New skill: `ha-nova:diagnose`.** Root-cause a concrete failure — "why didn't my morning automation run?" — from run traces, the error log, the system log, and bounded history windows, with an optional (and always reset) debug-level escalation.
- **New skill: `ha-nova:media`.** Control and browse your media players: play/pause, volume, source, speaker grouping, media libraries, and TTS announcements — with a feature check first, so it never calls something your player cannot do.
- **New skill: `ha-nova:camera`.** Ask to see a camera and the agent actually looks at the current frame — plus stream URLs and recording. Frames stay private: they never leave the conversation.
- **New skill: `ha-nova:mqtt`.** "Is my sensor even sending anything?" — listen to an MQTT topic for a few seconds and see what really arrives; inspect device discovery; publish with a hard guard on retained messages.
- **New skill: `ha-nova:notify`.** Send notifications to your phone and manage Home Assistant's persistent notifications, including mobile-app extras (actionable buttons, tag replace, priority) — and it tells you honestly that Home Assistant accepted a send, not that the phone displayed it.
- **New skill: `ha-nova:assist`.** Test your voice assistant without speaking: send an utterance and see what Assist really understood and did. Also manages Assist pipelines, which entities voice can see, and lists the available TTS/STT/wake-word engines.
- **New skill: `ha-nova:admin`.** Persons, zones, tags, and user accounts. Zone changes warn you which presence automations depend on them first; deleting the owner account, system accounts, or the relay's own account is refused outright.
- **New skill: `ha-nova:external-sources`.** "What was the temperature last summer?" — when the recorder purged it long ago but InfluxDB still has it. Queries your InfluxDB directly (read-only, your own credentials), since Home Assistant only writes there and cannot read it back.

- **Runs on every Home Assistant install now.** The relay also ships as a standalone container (`ghcr.io/markusleben/ha-nova-relay`), so Home Assistant Container and Core users — who cannot install Apps — are no longer locked out. Same code, same security model: your Home Assistant token still never leaves the server.

- **YAML configuration you can finally edit.** Template, REST and command-line sensors, packages and themes have no Home Assistant API — they only exist as files. The new `ha-nova:yaml-config` skill edits them through the relay's opt-in file access: read first, show a diff, back up, validate with Home Assistant before reloading, and verify the entity actually appeared. It works only if you switch it on: the NOVA Relay App has a new `file_access` option (`off` by default, then `read` or `readwrite`). Secrets, the recorder database, Home Assistant's internal storage, and anything executable (`custom_components`, `python_scripts`, `www`) stay off-limits in every mode.

## What To Watch (draft)

- The NOVA Relay App must be updated to 0.4.0 or newer: camera and MQTT need 0.3.0's binary and bounded-listening support, and YAML editing needs 0.4.0's opt-in file access. HA NOVA tells you if your relay is too old.

- Uninstall always prints the Home Assistant cleanup checklist now, including the access-token revocation step that was previously never mentioned.
- Set `HA_NOVA_NO_UPDATE_NUDGE=1` to silence the new update notices.
