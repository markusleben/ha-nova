# Safety guarantees

What HA NOVA promises, what enforces it, and what proves it. Every row names a file you can read and a test you can run — no adjectives.

Last verified: 2026-07-11 — `npm run verify`, `go test ./...`, and the live end-to-end run against a real, disposable Home Assistant (`bash scripts/e2e/disposable-ha/run.sh`), all green. Re-verify this date on the exact release commit before publishing.

The Home Assistant Link (formerly Home Assistant Cloud) rows below document the Beta's enforced contracts.
Every publication carries signed bundle provenance and passes the three-OS
release smokes; the maintainer works through the per-release Cloud checklist in
`docs/releasing.md`.

## Writes

HA UI parity batch 1 (0.29) adds raw writes the Home Assistant UI makes: integration enable/disable, rename and system options, ignoring a discovery, user account edits, general settings, ignoring a repair, exposing new entities to voice, and blueprint deletion (`cli/relay_raw_allow.go`). The raw guard refuses disabling, enabling, or changing polling of an integration entry that has a lock, alarm panel, or access cover, including one whose switch backs a `switch_as_x` access entity (removing that entry, one of its subentries, or the switch itself is refused the same way), and any access change (administrator flag, active state, local-only) to the owner's account, a system account, or the account HA NOVA uses; an unreadable registry or account list sends nothing. Access changes, time zone or unit changes, a new area or label on a device with a lock, alarm panel, or access cover, and blueprint deletion are typed; the rest are previewed. Proof: `cli/plan_raw_tier_test.go`.

HA UI parity batch 3a (0.31) adds automatic backup settings (`backup/config/update`, previewed; typed with a retention, which deletes older automatic backups), Labs features (`labs/update`, typed), statistics import (`recorder/import_statistics`, typed: stored rows for the same hours are overwritten), and analytics sharing (`analytics/preferences`, previewed). The raw guard refuses any backup settings change that sets or clears the encryption password (`create_backup.password`), changes which locations encrypt (`agents.<id>.protected`), marks the first automatic setup done (`automatic_backups_configured`), carries a `create_backup` or `agents` value it cannot read, or sends a partial schedule or retention block (Home Assistant resets the rest), on every route (relay, plan, chat, collect_events envelope). Adding a remote location reads the saved settings live and is refused while no key is saved or the read fails; `backup/generate` with its own `password` or a remote location is refused, since Home Assistant uploads without a key unencrypted; the encryption key stays in the Home Assistant UI, and reads keep hiding the stored password (`backup/config/info`). Proof: `cli/plan_raw_tier_test.go`.

Device deletion sends Home Assistant's own `config/device_registry/remove` (HA 2026.9+) as a typed raw plan, the same on a computer and in chat apps, after a metadata snapshot and a preview of the entities and consumers that go (`organize`). The raw guard refuses a device that has, or whose child devices have, a lock, alarm panel, or access cover, and HA NOVA's own App device; an unreadable registry sends nothing. There is no undo. Proof: `cli/device_delete_test.go`, `cli/plan_raw_tier_test.go`, `tests/skills/routing-contract.test.ts`.

Known limits of the Supervisor route: log text passes as the Supervisor returns it (except its `invalid options` lines), so a credential an App writes into its own log is not hidden. The route is on the plain bootstrap listener too, so a legacy shared token reaches it (that token already reaches every Home Assistant service). The options merge sends the stored options, defaults included, so they become the App's saved settings. Chat apps give every chat user the owner allowed the same reach, under the same tiers. Home Assistant Link does not carry the route; Supervisor access works only on the local connection. The manager role widens what a Relay defect could reach: the allowlist is the only boundary between a paired device and the Supervisor's App, store, and log APIs. The table is pinned to Supervisor 2026.10.3; a later Supervisor may change its paths or role table (`docs/work/2026-10-26-supervisor-role-spec.md`).
