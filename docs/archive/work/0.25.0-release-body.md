# v0.25.0 — release body (archived)

Shipped wording lives in `.goreleaser.yml`; this file archives the drafted
body for the record.

## What To Watch

- **Cloud Remote is macOS-only in this release.** The validated platform
  list is `darwin`: the Windows and Linux validation machines are no longer
  available, and Cloud publication stays gated on per-platform proof.
  Windows and Linux clients keep full local functionality; Cloud Remote
  there stays disabled while per-platform validation infrastructure is
  unavailable. Existing older installs are unaffected.

## New Features

- **Finish Cloud setup over SSH.** `ha-nova cloud add --remote-resume`
  resumes an existing, already-verified authorization checkpoint from a
  plain SSH session — no browser, no credential prompts; elevated and WSL
  sessions are still refused. Starting a new authorization still needs a
  desktop session.
- **Invalid integration credentials get a guided recovery.** When an
  integration's stored credential stops working and Home Assistant has not
  opened a reauthentication flow, HA NOVA now previews and runs the entry
  reload that makes Home Assistant re-validate it, then continues the normal
  reauthentication handoff.
- **Failed service calls now name the real cause.** A generic error that
  coincides with Home Assistant starting reauthentication for the affected
  integration is reported as exactly that, with a direct path into the
  recovery flow.

## Bug Fixes

- **Automation suggestions are honest about what already exists.** Duplicate
  detection now understands area and device labels, groups, and blueprint
  inputs; an automation that already exists but is disabled is offered for
  enabling instead of being silently skipped.
- **Replicating an automation to another room got stricter.** Disabled
  counterparts, group or label targets bound to the source room, and
  device-specific triggers stop the copy with a plain explanation instead of
  producing a replica that never runs.
